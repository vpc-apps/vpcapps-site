Security

Security: Go/No-Go Release Scorecard for Jira

Last updated 8 November 2026.

How the app is built

  • Atlassian Forge, Runs on Atlassian. The app is hosted entirely on Atlassian’s Forge platform. Atlassian’s deploy check reports it eligible for the Runs on Atlassian program: no remote servers and no outgoing connections to other services.
  • Read-only access. It asks for two scopes only: read:jira-work (to read projects, releases, issues and your own permissions) and storage:app (to keep the go/no-go limits). It never creates, changes or deletes issues.
  • Your permissions, nothing more. Reports are calculated in your browser from data Jira returns for you, so a user sees only what their Jira permissions allow.
  • Data stays in Atlassian. No issue data leaves Atlassian’s platform and your browser. The app stores only rule settings, in Forge hosted storage for your site. See the privacy policy.
  • Changes are checked on the server. Saving limits requires Administer Projects on that project or Administer Jira, checked by Atlassian’s platform as the user, and the values are validated strictly.
  • No credentials. The app handles no passwords, API tokens or shared secrets; Forge authenticates every call.
  • One outside file. The dashboard-gadget icon is an image hosted on vpcapps.net, fetched by the browser like any web image. No Jira data is sent with it.
  • Safe output. All Jira text is escaped on screen and in downloads; downloaded reports contain no scripts.

Reporting a vulnerability

Email support@vpcapps.net with “Security” in the subject. Please include the steps to reproduce, the affected version (the build number at the bottom of the app) and the impact you expect. Do not include real customer data.

  • Please give us reasonable time to fix an issue before disclosing it, and do not test against Jira sites you do not own.
