How to use

Release Readiness Scorecard for monday.com

Know if this release can ship, with the reasons. This board view turns your QA or bugs board into a GO / AT RISK / NO-GO verdict for a release, with the checks behind it, charts, a defect report quality check and release notes.

On this page: setup, what the verdict means, the six rules and how to change them, quality checks, release notes, printing and sharing, permissions, privacy and support.

Before you start

  • A monday.com board where each item is a defect (or a mix of defects and other work items), with a Status column.
  • Somewhere that says which release each item belongs to: board groups, a dropdown, a connected board, or similar. Without it the whole board counts as one release.
  • Optional but useful: priority, created and resolved dates, a description, environment, files and a reopen count.

Set up

  1. Install Release Readiness Scorecard from the monday.com apps marketplace (an account admin may need to approve it).
  2. On your QA or bugs board, add a view (the + next to the board’s views) and choose Release Readiness Scorecard.
  3. The welcome page explains the app. Click Set up columns.
  4. In Settings, check the suggested mapping (the app guesses from your column names), tick the status labels that mean done, and click Save settings.
  5. Pick a Release at the top. The scorecard appears.

Only Status is required. Everything else is optional, and the report says what is missing in a notice above it, never as a silent zero. One column cannot be used for two roles.

Done labels: a status label counts as done when monday.com marks it done (the green “Done” style) or by its name (Done, Fixed, Closed, Verified…). You can change the ticks in Settings.

Priority labels are read by name: Critical also covers Blocker, Highest, Urgent, P0, S0/S1 and Sev 0/1; High covers Major, P1 and S2. Labels with other names keep their own name and count in neither priority rule.

Timeline columns are not offered as a release, because a date range is not a release name. Use groups or a dropdown.

What the verdict means

Each rule compares a number with two limits: at or below the GO limit it passes; above GO but at or below AT RISK it is at risk; above AT RISK it fails. The overall verdict is the worst result of any rule.

VerdictMeans
GOEvery rule is at or below its GO limit.
AT RISKNo rule fails, but at least one is above its GO limit (and at or below its AT RISK limit).
NO-GOAt least one rule is above its AT RISK limit.
NO DATANo defects are linked to this release. An empty release never reads as GO. Check the Release column in Settings, or pick another release.

The verdict supports your release decision; it does not replace it. It reflects only what is recorded on the board.

  • “Open” means the status is not one of the done labels.
  • The four count rules can instead be set as a % of all defects in the release. Reopen rate and the evidence rule are always percentages.
  • Without a Reopen count column, the reopen-rate rule is shown as “not measured” and passes.

Changing the rules

Click Edit rules. Start from a template if you like, change the numbers (whole numbers; each AT RISK limit at or above its GO limit) and click Save rules. Use defaults goes back to the built-in limits. Choosing a template only fills the editor; nothing is saved until you click Save rules.

TemplateForIn short
StrictRegulated or enterprise releasesNo open critical or high defects, nothing left open for 30 days, a low reopen rate
StandardMost teamsThe built-in defaults in the table above
Fast-movingStartups and internal toolsLimits as a share of all defects, more room for open work; only critical defects block

Who can change them: settings and limits are saved per board and shared by everyone who opens that board’s scorecard. Board viewers and guests see them read-only (View rules). Any board member can change them.

Report views

The View menu chooses which reports you see, print in full and download: Executive (the verdict, a card per rule, the comparison and blockers), QA lead (everything) or Release manager (comparison, priority mix, defects found after the last release shipped, status by priority, age and assignee). When there is an earlier release with defects, the report compares this release with it.

Defect report quality checks

Each defect is checked for five things, rule-based (no AI). The checks are advisory: they show which defects are hard to verify.

CheckPasses when
Steps to reproduceA “Steps to reproduce” (or STR / Repro) heading, or a numbered list
Expected and actual resultBoth an expected and an actual result are written down
Environment statedThe Environment column, or browser / OS / device / build words
Evidence attachedA file in the Files column, or a link to a screenshot, video or log
Clear titleMore than 3 words, and more than “not working”, “issue” or “error”

The app reads the board’s columns only. Item updates are not read, so put the steps to reproduce in a Description column for the quality check.

Release notes

The report lists the release’s items grouped as new features, improvements, fixed defects and known issues, with a short summary paragraph. Copy as Text, Markdown or HTML copies every line, ready to paste into a changelog or an email. If the browser blocks copying inside monday.com, the text is selected for you to press Ctrl+C (Cmd+C on a Mac).

Print and download

  • Print summary (1 page): the verdict, the summary cards and the key charts on one A4 page.
  • Print full report: every report in the chosen view, over as many pages as needed.
  • Download shareable report: one HTML file with no scripts that opens in any browser, for people without monday.com access.

Use the app’s own buttons. The browser’s Print menu prints the whole monday.com page instead. Printed and downloaded reports contain item names, priorities and assignee names: treat them like any board export.

Limits

  • The app reads up to 10,000 items of a board; above that the report says partial data.
  • Without a Resolved date column, fix times are estimated from the item’s last update.

Permissions

The app asks for one permission: boards:read, to read the board’s name, groups, columns and items. It has no write permission, so it never changes your board. It does not read item updates, your account’s users or anything outside the board you open it on. It reads with your own monday.com access, so each person sees only what they are allowed to see.

The column mapping, done labels and rule limits are saved per board in monday.com’s own app storage. Nothing else is saved: no item content.

Privacy

  • The app runs in your browser on monday.com and is hosted by monday.com. VPC Apps has no server for it.
  • Board data is read only to build the report on your screen. It is not sent to VPC Apps or anyone else, and it is not stored or logged.
  • No AI, no analytics and no advertising inside the app.
  • A downloaded or printed report is a file on your device; you control who receives it.
